# Product documentation templates

Reusable **compact, exhaustive single-purpose** artifact skeletons for real product/project repositories. See [product-documentation rules](../../behavior/product-documentation.md), [L1–L11 levels](../../workflows/progressive-levels.md) and [develop workflow](../../workflows/develop.md).

Choose and adapt documents proportionally to the actual product. For significant work, favor **many distinct, linked, concise documents** over one monolith; do not omit valuable docs to minimize file count. Do not create empty irrelevant templates. In a small project a few subjects can be combined without losing explicit headings; for complex projects split by component/use case.

Use `docs/00-overview.md` (or existing index) to link real artifacts; preserve editable diagrams, approved/proposed distinctions, source code paths, test evidence and revision. Update affected docs together with code. The examples below are *templates*, not claims about an implemented product.
