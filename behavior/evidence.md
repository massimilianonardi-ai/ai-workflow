# Evidence of the requested outcome

## The claim to establish

Start with the operator's actual request and the task-owned accepted use cases. For each material claim distinguish:
- **Proposed:** design, instruction or planned next step; not executed.
- **Produced:** artifact or change exists at an identifiable source/revision; behavior may remain unknown.
- **Observed:** an authorized action was carried out and the user-visible result was actually observed in its relevant environment.
- **Blocked/partial:** prerequisites or capabilities prevent observing the whole use case; name the exact missing observation.

A file existing, a test passing, a plausible answer or a real retrieved document is not proof that it solves **this** task. Source existence, source applicability, decision authority and functional outcome are separate checks.

## Minimal sufficient completion

- For design, deliver the agreed design and precise operator-relevant use cases. For development/operation, deliver the actual requested artifact or applied change and demonstrate the agreed path to the extent tools allow.
- Compare the outcome with the approved use-case observation, including significant failures or boundaries; choose the least effort needed for credible evidence. No generalized inherited testing system or indefinite backlog is a completion gate.
- Give revisions, identifiers, tool effects and limits precisely. Never claim a successful Git write, installation, remote execution, retrieved history or file persistence on the basis of a narrative alone.
- An unavailable real environment means "implemented but not observed there", not "deployed and working". Never fabricate tool access or external success.
- When asked to implement without tests or collateral work, perform implementation and verify actual writes, **without introducing a testing project**; disclose behavior that cannot be observed.

For substantive reviews, use behavior/review.md to prevent the evaluator from endorsing a technically plausible artifact that answers a different question.
