# AI-Workflow v0.2.2 — alpha checkpoint persistence fix

**Type:** experimental alpha prerelease.  
**Scope:** per-response checkpoint execution rules, conservative runnable planner, GitHub connector runbook and regression tests.  
**State repository:** `massimilianonardi-ai/ai-work-state/dev`, no automatic deployment or production state migration.

## What changed

- **Every response** now requires an attempted GitHub conversation checkpoint, including responses that do not modify tasks.
- A reply writes the branch head and an immutable request record; task documents only change when genuinely needed.
- Section C explicitly instructs the assistant to check and invoke available authorized GitHub write tools *before* emitting the final marker.
- The separate outcomes `persisted`, `persisted_with_gaps`, `write_failed`, `storage_unavailable` and `write_not_attempted` prevent "nothing changed" from hiding a missing checkpoint.
- Previous `sync = pending` history is never silently fabricated: it can be recorded as explicit gaps while a newer checkpoint is safely saved.
- Optional `!aw sync` command requests manual reconciliation of the *current conversation's* pending state.
- Added executable `state/checkpoint-runtime.mjs` and GitHub connector action recipe, plus Node unit tests covering unchanged turns, partial recovery and read-back failures.

## Evidence and limitations

The Node test suite verifies the **checkpoint planner**, not automatic ChatGPT invocation. The protocol and connector runbook are operational instructions only when a host actually exposes writable GitHub tools and the assistant calls them. Earlier tests with no commits cannot be retroactively certified as saved.

The planner intentionally refuses unsupported task-state mutations and derived branch creation, which require a full, separately verified Git transaction. No native ChatGPT hook is installed, and no automatic guarantees are implied by publishing a tag or a Project instruction. Test a genuine conversation and verify new records under `ai-work-state/dev`.

Confirm actual GitHub permissions and test with `!aw sync` plus ordinary responses.
