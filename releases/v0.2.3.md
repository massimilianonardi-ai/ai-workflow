# AI-Workflow v0.2.3 — active persistence branch correction

**Type:** experimental alpha prerelease. **Change:** authoritative state write branch is now **`massimilianonardi-ai/ai-work-state/main`**.

## Fix

- Bootstrap section C, state protocol, GitHub connector runbook, and opt-in ChatGPT Project instructions target `ai-work-state/main` for all live conversation, request and task-state checkpoints.
- The executable checkpoint runtime rejects adapters targeting `dev` or the wrong repository (`WRONG_STATE_TARGET`), even when those adapters would otherwise be writable.
- Tests now assert the correct destination and prevent future branch regressions.
- The state store's `main` branch now contains its active persistence policy. `ai-work-state/dev` retains old synthetic fixtures only; no conversation data was migrated or invented.

## Safety and limitations

`ai-work-state` is currently a **public GitHub repository**. Until its visibility is changed to private, do not persist confidential conversations, secrets or sensitive task metadata. This release does not modify GitHub repository visibility.

Native ChatGPT per-turn execution is **not guaranteed** by Markdown rules or Node tests: install the versioned bootstrap in a dedicated ChatGPT Project with write-authorized GitHub connector, then verify a live checkpoint on `ai-work-state/main`. The immutable `v0.2.2` tag still points to the earlier dev-target version; update the project instructions to `v0.2.3`.
